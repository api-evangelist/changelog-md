# Keep a Changelog (CHANGELOG.md)

> Keep a Changelog is the community convention for a human-readable, Markdown-formatted
> CHANGELOG.md at the root of a project that records notable changes between versions.
> It defines a closed set of six change types (Added, Changed, Deprecated, Removed,
> Fixed, Security), YYYY-MM-DD release dates, an `Unreleased` section and a `[YANKED]`
> marker, and recommends pairing with Semantic Versioning. Current version: 2.0.0,
> released 2026-06-07. MIT licensed, created and maintained by Olivier Lacan, available
> in 28 languages.

IMPORTANT — Keep a Changelog publishes NO API. There is no base URL, no authentication,
no endpoints, no SDK and no MCP server. It is a specification served as static HTML from
GitHub Pages; the project's own AGENTS.md states "No backend." Do not attempt to call it.
The machine-readable surfaces are the raw specification pages and the project's own
CHANGELOG.md, listed below.

This file was GENERATED by API Evangelist from the apis.yml record and the artifacts in
this repository. keepachangelog.com does not publish an llms.txt of its own
(https://keepachangelog.com/llms.txt returned 404 on 2026-09-05).

## The format in one paragraph

A `CHANGELOG.md` at the project root opens with a `# Changelog` heading and a short
preamble naming the format and the versioning scheme. Releases are second-level headings
in reverse chronological order — `## [2.0.0] - 2026-06-07` — with an `## [Unreleased]`
section at the top for work not yet shipped. Under each release, third-level headings
group entries by change type: `### Added`, `### Changed`, `### Deprecated`, `### Removed`,
`### Fixed`, `### Security`. The six types are deliberately closed and do not grow. A
withdrawn release is marked `[YANKED]`. Each version links to a compare diff via a
Markdown reference link at the bottom of the file.

## What changed in 2.0.0

- The format is unchanged: six change types, YYYY-MM-DD dates, `Unreleased` and `[YANKED]`.
- Breaking: the page was restructured from a flat FAQ into integrated guidance, so some
  older section anchors no longer resolve; the tagline changed.
- Added guidance on marking breaking changes, choosing between Changed/Fixed/Security,
  leading a Security entry with its CVE, versioning schemes beyond SemVer, changelogs vs.
  release notes, monorepos and very large changelogs.
- Added automation guidance covering LLM-drafted changelogs with a brief for an
  `AGENTS.md`, Conventional Commits, and CI/CD.

## Related standards

- [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html): Recommended pairing; the specification itself adheres to it.
- [ISO 8601](https://www.iso.org/iso-8601-date-and-time-format.html): The mandated date format, YYYY-MM-DD.
- [Conventional Commits](https://www.conventionalcommits.org/): Discussed in 2.0.0 automation guidance.
